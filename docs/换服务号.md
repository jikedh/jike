• 要把微信服务号从 A 换到 B，核心不是只改 AppID/Secret。这个项目里登录、关注/扫码事件、菜单、素材、支付 JSAPI 都依赖服务
  号身份，迁移要按下面走。

  1. 微信公众平台先准备 B

  在 B 服务号后台确认：

  - B 已认证，具备网页授权、生成带参数二维码、自定义菜单、客服消息/被动回复等需要的权限。
  - 配置服务器地址：当前项目回调是 POST/GET /v1/wechat/verify。
  - 配置 Token、EncodingAESKey，要和项目配置里的 Wechat.Oa.Token、Wechat.Oa.AesKey 一致。
  - 配置网页授权域名，覆盖当前前端登录回调域名。
  - 如果有 JS 安全域名、业务域名、网页授权回调域名，也都要迁到 B。
  - 如果项目根路径还有公众号校验文件，目前代码写死了 /MP_verify_Qo75L06rsgZhmq0t.txt 和返回内容，需要按 B 后台给的新校验
    文件更新。

  2. 项目配置切换

  配置项在 etc/config-*.yaml 对应结构：

  Wechat.Oa.Ak      // 服务号 AppID
  Wechat.Oa.Sk      // AppSecret
  Wechat.Oa.Token
  Wechat.Oa.AesKey
  Wechat.Pay...

  要换：

  - Wechat.Oa.Ak：B 的 AppID
  - Wechat.Oa.Sk：B 的 AppSecret
  - Wechat.Oa.Token：B 后台服务器配置 Token
  - Wechat.Oa.AesKey：B 后台 EncodingAESKey
  - 如支付也跟 B 走，还要检查 Wechat.Pay.NotifyUrl、商户号绑定的 AppID、证书/APIv3 key 是否匹配。

  注意服务里 wechatservice.NewWechat() 和 wxpay.New() 都用了 sync.Once 单例，所以改配置后必须重启服务。

  3. 登录数据兼容是最大风险

  当前扫码登录绑定的是服务号 A 的 openid：

  - 扫码登录二维码由 internal/domain/user/logic/wechat.go 创建。
  - 用户关注/扫码事件里用 msg.FromUserName 作为 openid。
  - 数据落在 user_login：type=3 AND info=<openid>。
  - 网页授权登录也用 resAccessToken.OpenID 查 user_login.type=3。

  微信规则是：同一个用户在不同服务号下 openid 不同。换成 B 后，原来 A 的 openid 查不到，会被当成新用户注册，导致老用户账
  号、积分、订单等无法自动继承。

  可选方案：

  - 最稳：如果 A、B 都绑定同一个微信开放平台账号，用 unionid 做迁移/绑定。代码现在没有存 unionid，需要改登录逻辑和用户登
    录模型/绑定逻辑。

  - 次稳：上线迁移期让用户用老账号信息或手机号做二次绑定，把 B 的 openid 绑定到原用户。
  - 不处理：B 上所有微信用户都会成为新用户，这通常不可接受。

  4. 服务号功能迁移

  项目里服务号功能包括：

  - 关注/扫码登录欢迎语：internal/service/wechatservice/reply/event.go
      - 关注回复：欢迎关注 ...
      - 扫码回复：欢迎登录 ...

  - 菜单：internal/domain/wechat/cron/setmenu.go
      - 客服
      - 课程
      - uuid

  - 菜单点击回复图片 media_id 也在 event.go，这些 media_id 属于 A，换到 B 后一般失效，需要重新上传素材到 B，替换新的
    media_id。

  - 素材上传接口在 /v1/wechat/material/add-image，可用于向当前配置的服务号上传素材。
  - 支付通知在 /v1/wechat/pay-notify，如果支付 AppID/商户绑定变化，需要在微信支付平台同步配置。

  5. 切换顺序建议

  1. 在测试环境配置 B 的 AppID/Secret/Token/AESKey。
  2. 微信后台 B 配置服务器 URL /v1/wechat/verify 并通过校验。
  5. 执行或等待菜单设置任务，把菜单发布到 B。
  6. 验证：关注、扫码登录、网页授权登录、菜单点击、支付下单/回调。
  7. 处理老用户迁移方案，优先确认是否有开放平台 unionid。
  8. 生产配置切到 B，重启服务。
  9. 保留 A 一段时间用于通知用户迁移或兜底。

  当前代码里需要重点改/查的点

  - internal/service/wechatservice/wechat.go：服务号配置读取。
  - internal/domain/user/logic/wechat.go：扫码登录。
  - internal/domain/wechat/logic/base.go：微信回调、OAuth 登录、MP 校验文件。
  - internal/service/wechatservice/reply/event.go：欢迎语、扫码回复、菜单点击回复、media_id。
  - internal/domain/wechat/cron/setmenu.go：菜单定义。
  - internal/service/wxpay/wxpay.go：JSAPI 支付使用 Wechat.Oa.Ak 作为 AppID。

  结论：配置切换半天能做完，但“老用户从 A 迁到 B 后还能识别为同一账号”需要单独设计，最好先确认 A 和 B 是否绑定同一个微信
  开放平台并能拿到 unionid。

• 下面按“可落地切换”的顺序来做。重点：A、B 是两个服务号，用户 openid 会变，不能只改 AppID/AppSecret。

  一、切换前确认

  1. 确认 B 是服务号，并且已认证。
  2. 确认 B 是否和 A 绑定在同一个微信开放平台账号下。
      - 如果是同一个开放平台账号，可以用 unionid 做老用户识别。
      - 如果不是，A 的用户在 B 下无法天然识别为同一人，只能走重新绑定/迁移流程。

  3. 梳理当前服务号功能：
      - 扫码登录
      - 关注欢迎语
      - 扫码欢迎登录
      - 自定义菜单
      - 菜单点击回复图片
      - 网页授权登录
      - 微信支付 JSAPI
      - 支付回调

  二、准备 B 服务号后台

  登录 B 的微信公众平台后台：

  1. 配置服务器地址：
      - URL：https://你的域名/v1/wechat/verify
      - Token：和项目配置 Wechat.Oa.Token 保持一致
      - EncodingAESKey：和项目配置 Wechat.Oa.AesKey 保持一致
      - 消息加解密方式按当前项目能力选择，建议先保持和 A 一致。

  2. 配置网页授权域名：
      - 位置通常在“设置与开发 / 公众号设置 / 功能设置 / 网页授权域名”
      - 域名不要带 http:// 或 https://
      - 必须覆盖当前登录回调页所在域名。

  3. 配置 JS 接口安全域名、业务域名：
      - 如果前端在微信内调用 JSAPI、支付、分享等能力，需要同步配置。

  4. 配置微信支付关联：
      - 如果 B 继续使用当前商户号，需要确认商户平台已绑定 B 的 AppID。
      - JSAPI 支付里 appid 会使用 B 的服务号 AppID。
      - 支付授权目录、支付回调地址也要检查。

  三、修改项目配置

  项目配置结构在 internal/config/config.go，服务号配置是：

  Wechat:
    Oa:
      Ak:     B的AppID
      Sk:     B的AppSecret
      Token:  B后台服务器配置Token
      AesKey: B后台EncodingAESKey

  如果支付也切到 B，还要检查：

  Wechat:
    Pay:
      MchID:
      MchCertificateSerialNumber:
      MchApiV3Key:
      MchPriKeyPath:
      WxPayCertPath:
      NotifyUrl:

  注意：服务里用了单例初始化，改配置后必须重启服务。

  四、改代码里和 A 绑定的固定内容

  当前有几处不是纯配置：

  1. MP 校验文件
     在 internal/domain/wechat/logic/base.go：

  func MpVerify(ctx *gin.Context) {
      ctx.String(http.StatusOK, "Qo75L06rsgZhmq0t")
  }

  以及路由在 internal/domain/wechat/api.go：

  route.GET("/MP_verify_Qo75L06rsgZhmq0t.txt", logic.MpVerify)

  如果 B 的网页授权域名校验文件变了，需要替换文件名和返回内容。

  2. 菜单配置
     在 internal/domain/wechat/cron/setmenu.go。切 B 后要重新发布菜单。

  3. 菜单点击回复图片 media_id
     在 internal/service/wechatservice/reply/event.go。
     这些 media_id 属于 A，B 下通常不可用，需要把素材重新上传到 B，再替换新的 media_id。

  4. 欢迎语/登录语
     同样在 internal/service/wechatservice/reply/event.go。
     关注和扫码登录回复可以在这里调整文案。

  五、处理用户迁移

  当前微信登录绑定逻辑：

  - 扫码登录：A 的 openid 存在 user_login.info
  - 类型：user_login.type = 3
  - 登录查找条件：type=3 AND info=<openid>

  相关文件：

  - internal/domain/user/logic/wechat.go
  - internal/domain/wechat/logic/base.go
  - internal/models/user_login.go

  换到 B 后，同一个微信用户的 openid 会变。建议方案：

  1. 优先方案：使用 unionid
      - 确认 A、B 绑定同一个微信开放平台。
      - 修改登录逻辑，获取并保存 unionid。
      - 登录时优先按 unionid 找老用户，再绑定 B 的新 openid。
      - 避免老用户变成新账号。

  2. 临时方案：用户二次绑定
      - B 首次登录后提示绑定原账号、手机号或其他身份。
      - 后台把 B 的 openid 绑定到原 user_id。

  3. 不迁移
      - 最简单，但老用户会全部变成新用户。
      - 积分、订单、历史资料都会断开，不建议。

  六、测试流程

  测试环境先切 B：

  1. 启动服务：

  $env:MODE="api"
  go run . -conf etc/config-dev.yaml

  2. 微信后台 B 验证服务器配置是否通过。
  3. 测试 /v1/wechat/verify 是否能收到事件。
  4. 测试关注 B 服务号：
      - 是否收到欢迎语
      - 是否创建/绑定用户

  5. 测试扫码登录：
      - 调 /v1/user/get-scene-qrcode
      - 用微信扫码
      - 轮询 /v1/user/query-scene-status
      - 确认能登录

  6. 测试网页授权：
      - /v1/wechat/oauth-url
      - 回调 code
      - /v1/wechat/login

  7. 测试菜单：
      - 发布菜单
      - 点击菜单
      - 图片回复是否正常

  8. 测试支付：
      - 下单
      - JSAPI 调起支付
      - /v1/wechat/pay-notify 是否正常回调

  七、正式切换

  1. 备份当前生产配置。
  2. 确认 B 后台域名、服务器配置、支付配置全部生效。
  3. 更新生产配置为 B。
  4. 部署包含校验文件、media_id、欢迎语等修改的代码。
  5. 重启服务。
  6. 立即验证：
      - /health
      - 关注事件
      - 扫码登录
      - 网页授权登录
      - 菜单点击
      - 支付回调

  7. 观察日志和数据库：
      - user_login
      - wechat_scene_scan
      - 订单支付状态

  8. 保留 A 一段时间，用于通知用户迁移和回滚。

  如果 B 切换失败：

  1. 恢复 A 的配置：
      - Wechat.Oa.Ak
      - Wechat.Oa.Sk
      - Wechat.Oa.Token
      - Wechat.Oa.AesKey

  2. 恢复 A 的校验文件路由/内容。
  3. 恢复 A 的素材 media_id。
  4. 重启服务。
  5. 微信后台 A 重新启用服务器配置。
  6. 验证扫码登录、关注回复、支付。

  参考入口：微信公众平台后台 https://mp.weixin.qq.com/ ，微信开放平台 UnionID 机制说明可参考 https://open.weixin.qq.com/
  及相关开发文档。
